Picotron

Picotron is a fantasy workstation, which is a small imaginary computer that runs on your real one. It has a 480 × 270 pixel screen with 64 colours and a sound chip, and the tools for making games are built right into it, so the code editor, sprite editor, map editor and music editor all live inside Picotron itself. You write programs for it in Lua, which is a small programming language.

I like it for learning because there's nothing else to set up or install, we type some code into the editor and press a key and it runs. You don't need any programming experience for this lesson or for any of the ones after it.

We'll get it running and write a first program. Then we'll save it and break it, and finish with a quick tour of how a Demotron lesson page works.

Installing Picotron

Picotron is made by Lexaloffle, the people behind PICO-8. If you've used PICO-8, Picotron is more like a whole computer with its own desktop and file system, where PICO-8 is more like a Nintendo devkit.

Picotron is a paid program that runs on Windows, Mac and Linux, and you buy it at lexaloffle.com/picotron.php. Once you've paid they send you a download link, and future updates are included.

Download the version for your computer and unzip it, then start up the Picotron program that's inside. There's no installer or anything else to it.

Picotron is still in beta, so new versions turn up every so often and small things can change between them. The very bottom of every Demotron page says which version we made the lesson with, so if something in a lesson doesn't match what you see, compare versions first.

Workspaces

Each part of Picotron lives in its own workspace that fills the whole screen, and we switch between them with the icons at the top right of the screen.

The first four are the editors for code, sprites, maps and sound. The desk icon is the desktop where your files and folders are, and the little TV is the terminal where we type commands.

Two shortcuts save a lot of clicking. Escape flips between the desktop and the terminal, and Alt + Left and Alt + Right step through the workspaces one at a time (Option on a Mac). The icons do exactly the same job, so you can leave the keys until you want them.

A First Program

Click the code icon, the () at the top right. This is the code editor, and it's open on a file called main.lua. When Picotron starts a program it runs main.lua, so that's where our code goes.

Let's start with a tiny program. Click Copy, then click inside Picotron's code editor and press Ctrl + V to paste it in.

Lua
1function _draw()
2  cls(1)
3  circfill(240, 120, 30, 12)
4  print("hello, picotron!", 200, 170, 7)
5end

Once it's pasted in it should look like the screenshot below. Picotron colours the code for you. Words that belong to Lua itself like function and end come out pink. Picotron's own functions are green while numbers and text are blue, and the code panels on this site use the same colours.

Press Ctrl + R to run it. Picotron switches over to the program and runs it full screen, and what you get should match the one below, which is the real program running right in the page.

Runs right here in the page. Click it, then use the keyboard.

It clears the screen to dark blue, draws a light blue circle and prints a message underneath it. How each of those lines actually does that is what the next few lessons are about.

To stop the program press Escape, then Escape once more to get back to the code editor.

We'll go round the same loop in every lesson:

  • Copy the code and paste it into the code editor.
  • Press Ctrl + R and try it out.
  • Press Escape and change something.
  • Run it again.

Saving

The program we're working on lives in Picotron's memory, as the working cartridge. Cartridge is just Picotron's word for a project, meaning the code plus any sprites, maps and sounds that go with it. If we want to keep it we have to save it to a file.

Go to the terminal by pressing Escape from the desktop or clicking the TV icon. Type this in and press Enter.

save hello

Picotron saves the cartridge as hello.p64 and tells us it did.

After that Ctrl + S saves it again under the same name, so we only ever type save once. Next time we start Picotron, typing load hello in the terminal brings it back and Ctrl + R runs it.

If you've forgotten whether you called it hello or hello_final_v2_actually_final, ls lists the files in the current folder. Basics 1 covers the drive and these commands properly.

Error Messages

Sooner or later a program won't run, usually about thirty seconds after you start typing, and Picotron tells us why. Here's the same program with one letter missing, so circfill has been typed as circfil.

Read it from the left. /ram/cart/main.lua:3 means "in main.lua, line 3". After that comes what went wrong, which here is "attempt to call a nil value (global 'circfil')".

To call a function means to run it, and nil is Lua's word for nothing, so Picotron tried to run a function called circfil and found nothing by that name. Put the missing l back and press Ctrl + R again and it runs.

An error message almost always tells us where to look. Go to the line it names and read it slowly, checking the spelling, the brackets, the commas etc.

Buttons and Keys

Picotron programs read a small controller with four directions and two action buttons. Picotron calls the action buttons O and X, which are names that fit a gamepad and a keyboard equally well, so a program never has to care which one you're holding. On a keyboard the directions are the arrow keys, O is Z or C, and X is X or B.

The trouble is that an O written in the text looks like a key you should press, and there isn't one, so these pages always show the key you actually press. Z means Picotron's O button and X means its X button, and if you point at one it shows its Picotron name. In code they're buttons 4 and 5, which Basics 4 gets into.

The demos on these pages go by the letter printed on the key, so whatever your keyboard is you press the keys marked Z and X. Picotron on your computer goes by where the key sits instead. On a French AZERTY keyboard its O is the key marked W, and on a German QWERTZ keyboard it's the key marked Y, because those keys sit where Z is on an English keyboard. The "Controller Keys" section of the manual shows how to change which keys Picotron uses.

When you're stuck, ask in the #help channel of the Picotron Discord, and the link to it is at the bottom of every page.

Putting It Together

Now we've got Picotron installed and we know our way around its workspaces. We have a first program in main.lua that runs with Ctrl + R and stops with Escape, and it's saved as hello.p64, so load hello brings it back. When it breaks, the error message gives us the line and the name to look at.

What we don't know yet is what any of that code actually does, or where save hello put the file. Basics 1 answers the second one by looking at the drive, then Basics 2 starts taking the code itself apart.

Try This

  • Which numbers in the program decide where the message gets printed? Find them, then move the message so it sits above the circle.
  • Delete the end on the very last line and press Ctrl + R. Picotron points at a line that comes after the last line of your program. Why can't it point at the real mistake?
  • Picotron has a screenshot key, Ctrl + 6. Take a screenshot of your program while it's running, then track down where Picotron put it on your computer.
