Picotron

Picotron is a fantasy workstation: a small, imaginary computer that runs on your real one. It has a 480 × 270 pixel screen, 64 colours, a sound chip, and the tools for making games built in: a code editor, a sprite editor, a map editor and a music editor, all inside Picotron itself. Programs are written in Lua, a small programming language.

I like it for learning because there's nothing else to set up or install: we type some code, press a key, and it runs. No programming experience is needed, for this lesson or the ones after it.

By the end of this lesson we'll have Picotron running, a first program written and saved, a look at an error message, and a quick tour of how a Demotron lesson page works.

Installing Picotron

Picotron is made by Lexaloffle, the people behind PICO-8. It's a paid program for Windows, Mac and Linux, sold at lexaloffle.com/picotron.php. After paying, you're sent a download link, and future updates are included.

Download the version for your computer, unzip it, and start the Picotron program inside. That's the whole installation.

Picotron is still in beta, so new versions arrive from time to time and small things can change. The very bottom of every Demotron page says which version the lesson was made with. If something in a lesson doesn't match what you see, compare versions first.

Workspaces

Each part of Picotron lives in a workspace, a full screen of its own, and the icons at the top right of the screen switch between them:

The first four are the editors: code, sprites, maps and sound. The desk icon is the desktop, with the files and folders. The little TV is the terminal, where we type commands.

Two shortcuts save a lot of clicking. Escape toggles between the desktop and the terminal. Alt + Left and Alt + Right (Option on a Mac) step through the workspaces one at a time. The icons do the same job, so the keys can wait until they're wanted.

A first program

Click the code icon, the () at the top right. This is the code editor, open on a file called main.lua. Picotron starts a program by running main.lua, so that's where our code goes.

Here's a tiny program. Click Copy, then click inside Picotron's code editor and press Ctrl + V to paste it in:

Lua
1function _draw()
2  cls(1)
3  circfill(240, 120, 30, 12)
4  print("hello, picotron!", 200, 170, 7)
5end

Pasted in, it looks like the screenshot below. Picotron colours the code: words that belong to Lua itself, like function and end, in pink; Picotron's own functions in green; numbers and text in blue. (Demotron's code panels use the same colours.)

Press Ctrl + R to run it. Picotron switches to the program, full screen. This is what it should show, and it's the real program, running in the page:

Runs right here in the page. Click it, then use the keyboard.

It clears the screen to dark blue, draws a light blue circle and prints a message under it. How each line does that is what the next few lessons are about.

To stop the program, press Escape, then Escape once more to get back to the code editor.

That's the loop for every lesson: copy the code, paste it into the code editor, press Ctrl + R, try it, press Escape, change something, and run it again.

Saving

The program we're working on lives in Picotron's memory as the working cartridge. A cartridge is Picotron's word for a project: the code, plus any sprites, maps and sounds that go with it. To keep it, we save it to a file.

Go to the terminal (press Escape from the desktop, or click the TV icon), type this and press Enter:

save hello

Picotron saves the cartridge as hello.p64 and says so:

From then on, Ctrl + S saves it again under the same name, so save only needs typing once. Next time Picotron starts, load hello in the terminal brings it back, and Ctrl + R runs it. ls lists the files in the current folder, for when you can't remember what you called something. Basics 1 covers the drive and these commands properly.

Error messages

Sooner or later a program won't run, and Picotron says why. Here's the same program with one letter missing: circfill has been typed as circfil.

Read it from the left. /ram/cart/main.lua:3 means "in main.lua, line 3". Then comes what went wrong: attempt to call a nil value (global 'circfil'). "Call" means running a function, and "nil" is Lua's word for nothing. So Picotron tried to run a function called circfil and found nothing by that name. Fix the spelling, press Ctrl + R again, and it runs.

An error message almost always says where to look. Go to the line it names, read it slowly, and check the spelling, the brackets and the commas.

Buttons and keys

Picotron programs read a small controller: four directions and two action buttons. Picotron calls the action buttons O and X, names that fit a gamepad and a keyboard alike, so a program never has to care which one you're holding. On a keyboard the directions are the arrow keys, O is Z (or C) and X is X (or V).

An O in the text looks like a key you should press, and there isn't one, so these pages always show the key instead: Z means Picotron's O button and X its X button. Point at one to see its Picotron name. In code they're buttons 4 and 5, which Basics 4 covers.

The demos on these pages go by the letter printed on the key, so on any keyboard you press the keys marked Z and X. Picotron on your computer goes by where the key sits instead: on a French AZERTY keyboard its O is the key marked W, and on a German QWERTZ keyboard the key marked Y, because those sit where Z is on an English keyboard. The "Controller Keys" section of the manual shows how to change which keys Picotron uses.

When you're stuck, ask in the #help channel of the Picotron Discord (the link is at the bottom of every page).

Putting it together

In this lesson we:

  • installed Picotron and learned to switch between its workspaces
  • pasted a first program into main.lua, ran it with Ctrl + R and stopped it with Escape
  • saved it with save hello, and saw how load hello brings it back
  • read an error message for the line and the name it points at

Next, Basics 1 answers the obvious question about save hello: where did it put the file? Then Basics 2 starts taking the code itself apart.

Try this

  • Before you change anything, predict: which of the numbers in the program decide where the message is printed? Then move the message so it sits above the circle instead of below it.
  • Delete the very last line, the end, and press Ctrl + R. Picotron points at a line that's after the last line of your program. Read the message and work out why it can't point at the real mistake.
  • Picotron has a screenshot key: Ctrl + 6. Run your program, take a screenshot, and then find out where Picotron put it on your computer.
