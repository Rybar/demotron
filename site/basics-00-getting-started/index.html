Getting started

Get Picotron, find your way around it, and run your first program.

Welcome

Picotron is a fantasy workstation: a small, imaginary computer that runs on your real one. It has a 480 × 270 pixel screen, 64 colours, a sound chip, and everything you need to make games built right in: a code editor, a sprite editor, a map editor and a music editor, all inside Picotron itself. You write your games in Lua, a small, friendly programming language.

That's what makes it such a good place to learn. There's nothing to set up and nothing to install besides Picotron itself. You type some code, press a key, and it runs.

This first lesson gets you ready for all the others. We'll get Picotron running, find our way around, run a first program, save it, and see what happens when something goes wrong. At the end there's a quick tour of how Demotron's lessons work.

Getting Picotron

Picotron is made by Lexaloffle, the people behind PICO-8. It's a paid program for Windows, Mac and Linux, and you can buy it from lexaloffle.com/picotron.php. Once you've paid, you're sent a link to download it, and future updates come included.

Download the version for your computer, unzip it, and start the Picotron program inside. That's the whole installation.

Picotron is still growing (it's officially in beta), so new versions arrive from time to time and small things can change. Every Demotron lesson says which version it was made with at the very bottom of the page. If something in a lesson doesn't match what you see, check that first.

Finding your way around

Picotron looks like a tiny computer of its own, and that's exactly how it's meant to feel. Its different parts each live in their own workspace, a full screen of their own, and the icons at the top right of the screen switch between them:

The first four are the editors you'll use to make things: code, sprites, maps and sound. The desk icon is the desktop, with your files and folders. The little TV is the terminal, where you type commands.

A couple of keys get you around quickly. Escape toggles between the desktop and the terminal. Alt + Left and Alt + Right (Option on a Mac) step through the workspaces one at a time. You don't need to remember these now; clicking the icons always works.

Your first program

Click the code icon, the () at the top right. This is the code editor, and it's open on a file called main.lua. Picotron always starts your program by running main.lua, so this is where your code goes.

Here's a tiny program to try. Click Copy, then click inside Picotron's code editor and press Ctrl + V to paste it in:

Lua
1function _draw()
2  cls(1)
3  circfill(240, 120, 30, 12)
4  print("hello, picotron!", 200, 170, 7)
5end

It should look like this. Picotron colours the code as it goes: words that are part of Lua itself, like function and end, in pink; Picotron's own functions in green; numbers and text in blue. (Demotron's code panels use the same colours.)

Now press Ctrl + R to run it. Picotron switches to your program, full screen. This is what you should see, and it's the real program, running right here in the page:

Runs right here in the page. Click it, then use the keyboard.

That's your first Picotron program! It clears the screen to dark blue, draws a light blue circle, and prints a message under it. Don't worry about how yet; the next lessons take it apart line by line.

To stop the program, press Escape, and then press Escape once more to get back to the code editor.

That's the loop you'll use for every lesson: copy the code, paste it into the code editor, press Ctrl + R, play with it, press Escape, change something, and run it again.

Saving your work

The program you're working on lives in Picotron's memory as the working cartridge. A cartridge is Picotron's word for a project: your code, plus any sprites, maps and sounds that go with it. To keep it, save it to a file.

Go to the terminal (press Escape from the desktop, or click the TV icon) and type this, then press Enter:

save hello

Picotron saves your cartridge as hello.p64 and tells you so:

From then on, Ctrl + S saves it again under the same name, so you only need to type save once. Next time you start Picotron, type load hello in the terminal to get it back, and Ctrl + R to run it. Typing ls lists the files in the folder you're in, which is handy when you can't remember what you called something.

When something goes wrong

Sooner or later, a program won't run. That happens to everyone, every day, and Picotron does its best to tell you what went wrong. Here's the same program with one letter missing: circfill has been typed as circfil.

Read it from the left. /ram/cart/main.lua:3 means "in main.lua, line 3". Then comes what went wrong: attempt to call a nil value (global 'circfil'). "Call" means running a function, and "nil" is Lua's word for nothing. So Picotron tried to run a function called circfil and found nothing by that name. Fix the spelling, press Ctrl + R again, and you're back.

Error messages can look scary at first, but they almost always tell you where to look. Find the line it names, read it slowly, and check the spelling, the brackets and the commas.

How Demotron lessons work

Every lesson after this one looks like this:

  1. The code for the current slide. Copy puts it on your clipboard, ready to paste into Picotron.
  2. The demo: that same code, running. Click it to start, then click it again whenever you want it to listen to the keyboard. The arrow keys, Z and X are its buttons.
  3. Sliders change numbers in the running program while you watch. The highlighted number in the code follows along.
  4. The arrows step through the lesson's slides. Each slide has a new idea, a new demo and new code.
  5. The explanation for the slide.
  6. Try this: things to work out and change. These are the heart of every lesson. Copy the code into Picotron and have a go; there's no single right answer, and breaking things along the way is part of how everyone learns.

If you get stuck, the Picotron Discord's #help channel is full of friendly people (the link is at the bottom of every page).

Try this

  • Before you change anything, predict: which of the numbers in the program decide where the message is printed? Move the message so it sits above the circle instead of below it.
  • Delete the very last line, the end, and press Ctrl + R. Picotron points at a line that's after the last line of your program. Read the message and work out why it can't point at the real mistake.
  • Picotron has a screenshot key: Ctrl + 6. Run your program, take a screenshot, and then find out where Picotron put it on your computer.
